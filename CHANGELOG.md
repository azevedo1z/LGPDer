# Changelog

Relevant changes of the `lgpder` package, per version, with the publication date and the list of changes. The version policy is in the [Versioning](README.md#versioning) section of the README.

## Unreleased

The headless core becomes a plug-and-play product: one package with optional subpaths built on the core, which stays as the base.

### Package and tooling

- MIT license (`LICENSE` file); the package is no longer `private`.
- New subpaths `lgpder/storage`, `lgpder/scripts`, `lgpder/google`, `lgpder/evidence`, `lgpder/ui` and `lgpder/init`, each optional; whoever imports only the core does not load the rest. No module has a side effect on import (`sideEffects: false`), and every subpath can be imported on the server.
- The published package includes every `.d.ts` of `dist`, the guides of `docs/`, `README.pt-BR.md` and this `CHANGELOG.md`.
- Tooling: the check of the types with TypeScript 5.6 and 7 (`test:types-compat`) was removed; `publint` and `attw` remain; minimum coverage of 90%; size checked with `size-limit` (the core up to 3 kB and all the subpaths together up to 15 kB, gzipped); the direction of the dependencies between the core and the layers enforced by ESLint; CI on GitHub Actions with `npm run check`.
- Error messages, comments and JSDoc in English, keeping the `[lgpder]` prefix.

### Core (`lgpder`)

- New option `maxAge`, in milliseconds (default: 365 days), and new property `ConsentManager.maxAge` with the effective value. Grants and refusals expire: expiry is evaluated, with the configured clock, on hydration and in `restore`, and an expired decision, or one dated after the clock, is discarded and the purpose goes back to `'pending'`. If the clock throws or returns an invalid value in that evaluation, the decisions evaluated are discarded, without error. Creation calls the clock at most once, and only when the hydrated record has valid decisions; so does `restore`. Expiry is never evaluated continuously, to keep the snapshot stable: a long-lived tab notices it on the next restore with a new record or on the next load.
- The default clock returns the start of the UTC day of `Date.now()`, so that `decidedAt` does not work as a pseudo-identifier. The `now` option still allows more precision.
- The validation of the configuration and of `decide` is direct, for type and format, without the hardening against a polluted prototype: non-enumerable properties of `purposes`, `now` and `maxAge` and an inherited `purposes` are now read, and the exception of a getter of `options.record` now propagates. The refusal of unknown keys, the list of reserved ids and the full hardening of the read of the record remain, including reading `options.record`, `now` and `maxAge` only as own properties: an inherited value is ignored and neither grants nor revives decisions.

### Storage (`lgpder/storage`)

- `connectStorage(consent, { storage, key, crossTab })`, which replaces the recipe `examples/consent-store.ts` (removed): adopts the saved record on connection and before each decision, writes only decisions and adoptions, confirms each write by reading it back and removes the saved record when the write is not confirmed. It adds: a read before writing a decision made on the manager itself (with the saved record changed or unreadable, it removes instead of overwriting), no write of a decision already superseded by another change made during its delivery, the removal of a saved record without any decision, `isPersisted()`, sync between tabs on by default (the `storage` event with `localStorage`; a `BroadcastChannel` with the cookie and with an adapter of the application; `pageshow` and `visibilitychange`) and handles that throw after `destroy()`. Without `document`, as on the server, the storage is never touched.
- Adapters `localStorageAdapter({ key })` and `cookieAdapter({ key, maxAge })`. The cookie uses `Path=/`, `SameSite=Lax`, `Secure` on HTTPS and `Max-Age` equal to `maxAge` rounded down to seconds; a repeated cookie name is a read failure, and the removal also reaches the parent domains.
- `isPersisted()` is also `true` while the memory is still the hydration of the saved text, such as one with purposes of another configuration or with expired decisions, so a revocation that comes from another tab reloads it.

### Scripts (`lgpder/scripts`)

- `connectScripts(consent, { purposes, revocation, onRevoke, renderPlaceholder, canReload, debug })` blocks `<script type="text/plain" data-consent="...">` (inline or with `data-src`), `<iframe data-consent data-src>` and `<img data-consent data-src>` until every purpose listed is granted. The activated script is recreated with the other attributes, the `nonce` and `async = false`, and is never run again; activated elements get `data-consent-active`, read by later instances. A `data-consent` that is empty or names a purpose not configured never activates. Elements inserted later are processed by `scan(root)`.
- On a revocation (a decision, or a restore that came from another tab, also by expiry): iframes and images are blocked again, the cleanups of `onGranted(purpose, fn)` are called, the cookies of the purpose are removed (the built-in lists of `google-analytics` and `google-ads` plus own patterns with a trailing `*`, on the host and on each parent domain, with `Secure` on HTTPS) and `onRevoke({ purposes, requiresReload })` is called. If code was left running, the `'reload'` mode (default) reloads the page once, in a microtask and only if `canReload()` allows it; a refused reload blocks neither the next ones nor the next activations. `wouldReload(choices)` anticipates this rule. On connection, the cookies of the purposes that are not granted are removed. With `renderPlaceholder`, each blocked iframe shows a placeholder whose `load()` loads only that content, without recording a decision. With `debug: true`, warnings in the console about scripts of the known integrations without `data-consent` and about scripts with `data-consent` without `type="text/plain"`. Without `document`, the handle does nothing.
- The lists of `integrations` and `cookies` are read only by their own indexes, so a hole is refused even with a polluted `Array.prototype`. An item, or the purpose of `onGranted`, that is an object or a function is named in the error by its type, without calling its code.

### Google Consent Mode (`lgpder/google`)

- `connectGoogle(consent, { purposes, debug })` drives the Google Consent Mode v2. Each purpose declares the types it controls, through `consentMode` or the built-in integrations (`google-analytics` controls `analytics_storage`; `google-ads` controls `ad_storage`, `ad_user_data` and `ad_personalization`). A type is `'granted'` only when every purpose that controls it is granted, and the types without a purpose stay `'denied'`; the seven types are always sent. The layer sends `gtag('consent', 'update', ...)` on connection and on every notification, from the current state of the manager, through `window.gtag` when it exists or through `window.dataLayer` (with the `arguments` object, as the official snippet does), without defining `gtag`. If the `dataLayer` has no consent default, the layer pushes one, with every type `'denied'` and `wait_for_update: 500`, before the first update. Errors of `gtag` or of the `dataLayer` of the page are rethrown in a microtask, without stopping the layer. The handle has `destroy()`, which stops following the manager without sending anything, and `withdraw()`, which also sends every type `'denied'`. Without `document`, the handle does nothing.
- `consentDefaultSnippet` has the text of the script that sets that default in the `<head>`, before the Google tag. Its CSP hash is `'sha256-bwiEGrWus2Rs6F3b0yuALxS0J1DFbgWl4lLMtYRMl7E='`.

### Evidence (`lgpder/evidence`)

- `connectEvidence(consent, { endpoint, onDecision, onError })` hands the application the evidence of each decision of the data subject. Only changes with source `'decision'` count; restoring, syncing and hydrating never do. `onDecision(change)` is called first and, with `endpoint`, the layer sends by `POST` a JSON with the record after the decision, the changed purposes and the version of each versioned purpose, without an identifier, a user agent or an instant other than the `decidedAt` of the record. The send uses `navigator.sendBeacon` and, if it is missing, returns `false` or throws, `fetch` with `keepalive: true`, `credentials: 'same-origin'` and `redirect: 'error'`. On the `fetch` path, a network failure, a redirect or a response outside 2xx is reported to `onError`; the outcome of a beacon accepted by the browser cannot be observed. No failure affects the consent or is sent again. The beacon carries the cookies of the endpoint and follows redirects; on an endpoint of another origin, it needs a CORS preflight that accepts credentials. `endpoint` is resolved against the address of the page and must use HTTPS, or HTTP on `localhost`, `127.0.0.1` or `[::1]`; `endpoint` or `onDecision` is required, and the options are read only as own properties. Exceptions of `onDecision` and `onError` are rethrown in a microtask. Without `document`, the handle does nothing.

### Components (`lgpder/ui`)

- `mountUi(consent, { actions, purposes, texts, wouldReload, floatingButton })` mounts the banner, the preferences center and the floating button as Web Components (`lgpder-banner`, `lgpder-preferences`, `lgpder-button`) with an open shadow root, inserted at the start of the `body` (after `DOMContentLoaded`, while the document loads). The elements are defined on demand by `mountUi` and `createPlaceholder`, not on import, so the package keeps `sideEffects: false`; a tag already defined by another copy of the library throws before any effect. Decisions go only through `actions` (the actions of the storage or the manager itself) and on an explicit action of the data subject. The banner shows while some purpose without `individualGrant` is `'pending'` (first visit, expiry, new version or storage failure), lists the purposes "Aceitar todas" reaches and has "Aceitar todas" (`grantAll`), "Rejeitar todas" (`denyAll`) and "Personalizar", with the same emphasis. The center groups the purposes by category (a flat list when none declares one; "Outras finalidades" for the ones without), has one switch per purpose, shows the pending ones off, highlights the ones with `individualGrant` and has the informative section of the necessary cookies; on save, it records the switches changed and, as refused, the pending ones without `individualGrant`, without writing back what was not touched. The save button becomes "Salvar e recarregar" when `wouldReload` says the choices reload the page. `openPreferences(list)` opens only the listed purposes. The floating button shows with the banner and the center closed, unless `floatingButton: false`. An action that throws keeps the banner or the center open, and the error is rethrown in a microtask.
- `createPlaceholder(consent, { actions, purposes, texts })` returns the renderer of the placeholder (`lgpder-placeholder`) for the `renderPlaceholder` of `lgpder/scripts`: it names the purposes of the iframe, "Carregar" loads only that content without recording a decision and "Permitir sempre" grants the purposes of the iframe; the placeholder takes the `width` and `height` of the iframe.
- Accessibility (WCAG 2.2 AA): the banner as a labelled region and first in the tab order, the center as a modal dialog with a focus trap, `Esc` closes without saving and the focus goes back to whoever opened it (or to the floating button), switches with `role="switch"` and `aria-checked`, a banner never taller than the viewport, which scrolls its content past that height, `scroll-padding-bottom` on the root while the banner shows, minimum contrast of 4.5:1 for text and 3:1 for the focus and the switches, targets of at least 24 by 24 px. Checked with axe-core in the tests; `target-size` is checked on the CSS, since axe does not measure it without layout.
- Theme through CSS custom properties (`--lgpder-font-family`, `--lgpder-color-background`, `--lgpder-color-text`, `--lgpder-color-muted`, `--lgpder-color-primary`, `--lgpder-color-primary-text`, `--lgpder-color-border`, `--lgpder-color-focus`, `--lgpder-radius`, `--lgpder-z-index`, `--lgpder-shadow`) and `::part`. Texts in Brazilian Portuguese exported as `ptBR`; `texts` replaces fields per group and `categories` per key, and another language is a complete `UiTexts`. Texts are always inserted as text, never as HTML. Without `document`, the options are validated and the handle does nothing.
- `openPreferences(list)` reads the list only by its own indexes, and names an item that is an object or a function by its type, without calling its code.
- The CSP hash of the style sheet of the components is `'sha256-4ydU48/z3O6bG7Uy7CrY8iBC4yxZjQd3PBxuXb7XpV4='`.

### Single entry point (`lgpder/init`)

- `init(options)` creates the manager and connects every layer in one call. Each purpose takes, together, the keys of the core (`version`, `category`, `individualGrant`), the texts (`title`, `description`), `integrations`, `cookies` and `consentMode`, and `init` hands each part to its layer; the other options are `storage`, `revocation`, `onRevoke`, `maxAge`, `now`, `endpoint`, `onDecision`, `onError`, `necessary`, `texts`, `floatingButton` and `debug`. Connection order: storage, google (only when some purpose maps a Consent Mode type), evidence (only with `endpoint`, `onDecision` or `onError`), placeholder and components, and last scripts; a layer that refuses its options undoes the ones already connected before rethrowing the error, leaving no component, listener or activated script, and a google layer already connected sends every type `'denied'`. The reload of a revocation happens only with the record confirmed in the storage. `record` is refused (an external record comes in through `adopt`), and so is, with `storage: 'cookie'`, a cookie pattern that matches the cookie `lgpder` of the record. In the browser, a second `init` while another is alive throws. It returns `manager`, the actions of the storage (`decide`, `grantAll`, `denyAll`, `adopt`, `sync`), `openPreferences`, `onGranted`, `scan` and `destroy`, which disconnects everything and makes the other functions throw. Without `document`, it works in memory with the layers inert.
- The example of section 3 of the specification became the acceptance test, with at most 15 lines of configuration.

## 0.1.0 (unpublished)

First version of the core.

- The `createConsentManager` function, the only runtime export, and the types `ConsentManager`, `ConsentOptions`, `PurposeConfig`, `ConsentStatus`, `DecidedStatus`, `ConsentChoices`, `ConsentDecision`, `ConsentRecord`, `ConsentSnapshot`, `ChangeSource`, `ConsentChange` and `ConsentListener`.
- Decisions per purpose, with the effective status `'pending'`, `'granted'` or `'denied'`. Only `'granted'` authorizes, and the absence of a decision is `'pending'`.
- Atomic operations `decide`, `grantAll`, which does not reach purposes with `individualGrant: true`, and `denyAll`, which reaches all of them.
- Optional opaque version per purpose: a decision recorded under another version is `'pending'` and flagged in `outdated`, without being a revocation.
- Optional typed category, without state of its own.
- Serializable record in format `1`, hydration through `options.record` and adoption of external records through `restore`, with strict validation that never throws and discards whatever is invalid.
- Synchronous notifications with a source (`'decision'` or `'restore'`), only when the record changes, with a FIFO queue for reentrancy and errors of listeners rethrown in a microtask.
- Frozen public objects, stable references and a server snapshot for SSR and `useSyncExternalStore`.
- Programming errors as native `TypeError` and `RangeError`, with fixed messages in Portuguese.
- ESM-only package, without runtime dependencies, without access to the network or to storage and without side effects on import.
- Persistence and cross-tab sync recipe in `examples/consent-store.ts`, tested in the repository and reproduced in `docs/persistencia.md`; the file of the recipe was not part of the published package.
- Documentation in a short README and in the guides `docs/api.md` (API reference, typing, errors, notifications, SSR and React), `docs/persistencia.md` (recipe, bindings to `localStorage` and to the cookie, cross-tab sync and evidence of consent) and `docs/lgpd.md` (legal obligations, good practices and technical decisions per topic, responsibilities of the application and sources), included in the published package.
